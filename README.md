# 荒川ドローンレース — コースは Z3 が設計する

*Arakawa Drone Race — the course is designed by Z3.* Built for **Built with Claude: Japan 2026** (Nov 2–10, 2026).

- **デモ**：https://taketonomy.github.io/arakawa-drone-race/ （地図の上で機体が飛び、スライダーで sat/unsat が切り替わる）
- **スライド**：https://claude.ai/artifact/2YrbmdVz3ypLePhnm6kR8c

足立区を流れる荒川の上で（架空の）ドローンレースを開くとしたら、どんなコースなら安全で、ルールに合っているか。
条件を論理式で書き、**Z3 に条件を満たすコースと開催日を探させ**、2D の地図の上で機体を飛ばして見せます。
条件を厳しくすると「そんなコースは存在しない」と証明され（unsat）、どの条件同士がぶつかったかを示します。

**誰の、どの作業を解決するか：** 川の上でドローンのイベントを開きたい主催者が、申請の前に
「ルールを全部満たすコースと日程が存在するか」を確かめる作業。

> 架空の大会で、実際の開催提案ではありません。法令の条件は単純化した仮説のルールです。

## 仕組み

1. **川の区間**：OpenStreetMap から荒川の水面と橋を取り、橋と橋の間で一番長い区間を選ぶ。
2. **川の座標**：区間を「中心線に沿った距離 `s`」と「中心線からの横のずれ `d`」で表す。
   「ゲートが水の上にある」が `|d| ≤ 川幅/2` という線形の不等式になり、Z3 で扱いやすい。
3. **条件（Z3）**：

   | # | 条件 |
   |---|---|
   | C1 | コースは水面からはみ出さない |
   | C2 | 岸（観客エリア）から一定の距離をとる（地図のスライダーで 30〜100 m） |
   | C3 | 橋から 30 m 以上離れる |
   | C4 | 高度は 150 m 未満（レースは 5〜30 m） |
   | C5 | ゲートの間隔は 80〜250 m |
   | C6 | 左右に振る（中心線から 15 m 以上、交互） |
   | C7 | 既存の飛行計画（国交省の公開データ、足立区 1,672 件）と時間・場所が重ならない週末を選ぶ |
   | C8 | コース全体の長さは 600〜1,800 m |

   C1〜C8 はゲート（点）の条件。機体が実際に飛ぶ**経路**には次の条件をかける。
   経路は、ゲートの間を川の座標で直線に結び（`d` を `s` に比例して変える）10 m ごとの全地点を通り、
   帰りは中心線（`d = 0`）を戻る。地図の機体はこの経路をそのまま飛ぶ。

   | # | 条件（経路） |
   |---|---|
   | P1 | ゲートの間の経路も水面の上で、岸から C2 の距離を保つ |
   | P2 | 経路が橋に近づかない（橋をまたがない、くぐらない） |
   | P3 | 経路が既存の飛行計画と時間・場所で重ならない |

   Z3 は P1〜P3 を 10 m ごとの全地点で証明する。そのうえで `verify_path` が、実際の折れ線を
   shapely で厳密な形状として検査し直す（Z3 のモデルとは独立した検算）。合格しないとビルドは止まる。
   川幅は、橋と直角な断面の長さではなく「中心から岸までの最短距離」で抑えるので、曲がった所でも
   岸に寄りすぎない。

   コースがあるか（sat / unsat）を確かめ、ないときは最小の衝突集合（unsat core）を返す。
   あるときは「一番早い週末 → 一番長いコース → 一番大きく振るコース」の順に最適化する。
4. **地図**：`docs/index.html` は 1 ファイルで完結（Leaflet を同梱、背景は地理院タイル）。

## 使い方

```bash
pip install z3-solver shapely pytest   # Python 3.14 で z3-solver のビルドに失敗するときは z3-solver==4.12.6.0
python src/fetch_osm.py      # 荒川の水面と橋を OpenStreetMap から取得 → data/osm_arakawa.json
python src/build.py          # 解いて docs/index.html を書き出す
python -m pytest -q tests    # テスト（合成した川で検証）
```

区間を指定するとき：`python src/build.py --pick 西新井橋 千住新橋`（OSM の橋の名前）。

## 状況（2026-11-02）

荒川の実データ（OSM、2026-11-02 取得）で動かした結果：

- **区間**：鹿浜橋 〜 首都高速中央環状線（江北JCT の横断部）。長さ 1,921 m、水面の幅 132〜198 m。
  橋と橋の間で一番長い区間を自動で選んだもの。
- **sat / unsat**：岸からの距離（C2）が **81 m までは sat、82 m から unsat**（`build.py` が二分探索で
  求めた境目で、スライダーにも 81 と 82 を自動で入れている）。
  - 82 m の unsat core は C2・C6・C8・P2。岸から 82 m 離して左右に 15 m 振れる所は区間の一番広い
    所だけで、そこを橋に近づかずに 600 m 以上続けることができない。
  - 90 m では C2・C6、100 m では C2 だけ（区間で一番広い所でも幅が 200 m に届かず、両岸から
    100 m 離れた地点が水面上に一つもない）。
  - unsat core は「衝突する条件の最小の組」の一つで、組は一通りとは限らない。
  - この区間では、ゲートだけの条件（C1〜C8）でも境目は同じ 81 / 82 m。経路の条件 P1〜P3 は、
    81 m までのどのコースでもゲートの間が安全であることを保証している。経路の条件で初めて
    unsat になる例（川幅が途中で狭くなる所）は、合成した川のテストで確かめている。
- **P1 は正確な条件**：ゲートの間の経路 `d(j)` を各地点でそのまま判定する（ゲートのずれ×位置の
  積が入る非線形の式。値が有界な整数なので Z3 が判定できる）。最初は線形にするために安全側に
  寄せた近似を使っていたが、実データで 81 m を誤って unsat にした（ゲートだけで解いたコースの
  経路は実際には岸から 81.3 m 離れていた）ので、正確な式に替えた。
- **経路の検査**：sat の 7 通り（30〜81 m）すべてで、Z3 の経路（10 m ごと）と `verify_path` による実際の折れ線の
  検査が合格。
- **開催日**：すべての sat で 2025-01-04（土）10:00〜12:00。先約で見送った週末は 0 回。
  区間に重なる既存の飛行計画は 44 件あるが、**44 件すべてが平日**（大半が 9 時台の開始）で、
  週末の枠とは一度も重ならない。このデータでは C7・P3 が開催日を動かすことはない
  （日程がずれる動きは、合成した川のテストで確かめている）。
- **川の水面の取り方**：OSM では荒川の水面の大半が名前の無い `water=river` で、`name=荒川` は
  約 1 km の 1 片だけ。そこで川の水面をすべて取り、名前付きの片とつながる部分だけを残す。
  ほかの名前の川（隅田川、新河岸川 など）は除き、さらに幅 60 m 未満の水路・入り江・池
  （堤防沿いの綾瀬川、芝川、ゴルフ場の池 など）を落として本流だけにする。地理院タイルと重ねて確認済み。
- テスト 13 件（合成した川 12 件＋水面の取り方 1 件）。
